# 09 · 安全与风控（SEC）

[← 返回总览](./README.md)

## 1. 模块概述
贯穿所有模块的安全要求：防刷、防攻击、敏感数据保护、审计追踪。本文档定义“必须做到什么”，具体实现方案在技术设计文档中展开。

## 3. 详细要求

### 3.1 接口限流（SEC-01）
基于 Redis 令牌桶，超限返回 429 + `Retry-After`。

| 接口 | 维度 | 限制 |
|---|---|---|
| 全局默认 | IP | 300 次 / 分钟 |
| 注册 | IP | 5 次 / 小时 |
| 登录 | IP | 20 次 / 分钟；账号维度见 AUTH-08 |
| 发送邮件类（验证、重置、验证码） | 邮箱 + IP | 1 次 / 60 秒，10 次 / 天 |
| 创建订单 | IP | 10 次 / 分钟 |
| 文件上传 | 商家 | 60 次 / 分钟 |
| 下载 | 订单 | 见 DLV-04 |
| 举报 | IP | 10 次 / 天 |
| 支付回调 | — | 不限流（依赖验签） |

### 3.2 业务防刷（SEC-02）
| 风险 | 措施 |
|---|---|
| 恶意下单占用卡密库存 | 同一邮箱同一商品最多 3 个待支付订单；同一 IP 最多 5 个待支付订单；预占 15 分钟自动释放 |
| 免费商品被批量领取 | 同一邮箱同一免费商品只能领取 1 次；同一 IP 每小时最多领取 10 次 |
| 批量注册 | 拒绝一次性邮箱域名；IP 限流；异常时启用图形验证码 |
| 查单验证码爆破 | 每个验证码最多尝试 5 次；同一邮箱每天最多 10 次 |

### 3.3 防账号枚举（SEC-03）
- 登录失败统一提示“邮箱或密码错误”。
- 找回密码、已购查询获取验证码：无论邮箱是否存在，提示相同，响应时间保持一致。
- 注册时“邮箱已注册”可以提示（体验优先），但受注册限流保护。

### 3.4 认证安全（SEC-04）
- 密码使用 bcrypt（cost = 12）存储。
- Access Token：JWT，15 分钟有效，存在内存中，不写入 localStorage。
- Refresh Token：随机字符串，存于 `HttpOnly; Secure; SameSite=Lax` Cookie，Redis 中存哈希；每次使用后轮换，检测到重复使用则作废该用户所有令牌。
- 修改密码、重置密码、封禁账号时，作废全部 Refresh Token。

### 3.5 XSS / CSRF / 注入防护（SEC-05）
- **XSS**：React 默认转义；商家 Markdown 使用白名单渲染（允许标题、段落、列表、链接、图片、代码、表格；禁止 HTML 标签、`javascript:` 链接、事件属性）；外部链接统一加 `rel="noopener noreferrer nofollow"`。
- **CSRF**：Refresh Token Cookie 使用 `SameSite=Lax`；改变状态的接口只接受 `Authorization` 头中的 Access Token，不接受 Cookie 鉴权。
- **SQL 注入**：只使用参数化查询（GORM 占位符），禁止拼接 SQL。
- **开放重定向**：登录后跳转的 `redirect` 参数只允许站内相对路径。
- **越权**：所有商家接口在服务端根据登录身份获取 `shop_id`，不使用前端传入的店铺 ID；资源 ID 查询必须带 `shop_id` 条件。

### 3.6 敏感数据加密与脱敏（SEC-06）
| 数据 | 存储 | 展示 |
|---|---|---|
| 商家支付宝应用私钥 | AES-256-GCM 加密，主密钥来自环境变量 / 密钥管理服务，不入库、不入代码仓库 | 永不回显 |
| 卡密 | AES-256-GCM 加密存储 | 后台默认脱敏，点击查看并记录审计日志 |
| 买家邮箱 | 明文（需要查询）+ 访问控制 | 列表脱敏 `a***@qq.com`，详情完整 |
| 订单令牌、重置令牌 | 只存 SHA-256 哈希 | — |
| 日志 | 禁止记录密码、私钥、完整卡密、令牌 | — |

### 3.7 文件上传安全（SEC-07）
- 服务端校验扩展名白名单 + 文件头魔数，两者不一致则拒绝。
- 文件直传对象存储使用服务端签发的预签名上传 URL（限定路径、大小、类型、10 分钟有效）。
- 存储路径使用随机 ID，不使用用户提供的文件名。
- 图片上传后服务端重新编码（去除 EXIF 隐私信息、防止图片马）。
- 商品文件放在私有桶，图片放在公有桶（经 CDN）。

### 3.8 审计日志（SEC-08）
记录以下操作：时间、操作人、角色、IP、操作类型、对象、变更前后摘要。保留 1 年，不可修改和删除。

| 类别 | 操作 |
|---|---|
| 账号 | 登录成功 / 失败、修改密码、退出其他设备 |
| 收款 | 修改支付宝配置、切换环境 |
| 商品 | 上下架、删除、导出卡密、查看完整卡密 |
| 订单 | 退款、补发、修改买家邮箱、重置访问链接、导出订单 |
| 管理员 | 全部操作 |

### 3.9 支付安全（SEC-09）
- 回调必须验签，并核对 `app_id`、订单号归属、金额。
- 以服务端订单金额为准，前端传入的价格只用于“价格变化”提示，不参与计费。
- 订单状态变更全部使用条件更新 + 分布式锁，详见 [04-order-payment.md](./04-order-payment.md)。
- 回调、主动查询、退款的原始报文全部留存 180 天。

### 3.10 数据备份与恢复（SEC-10）
- MySQL：每日全量备份 + binlog，备份保留 30 天，异地存储；每月演练一次恢复。
- 对象存储：开启版本控制，删除的文件保留 30 天。
- 目标：RPO ≤ 1 小时，RTO ≤ 4 小时。

### 3.11 安全响应头（SEC-11）
`Strict-Transport-Security`、`Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`（买家页面允许商家后续嵌入时单独配置）、`Referrer-Policy: strict-origin-when-cross-origin`（交付页为 `no-referrer`）。

### 3.12 个人信息保护（SEC-12）
- 遵循《个人信息保护法》：隐私政策明确收集项（买家邮箱、IP、设备信息）和用途。
- 最小化收集：买家只需要邮箱。
- 商家对买家邮箱的使用限于订单服务；V2 营销邮件需买家单独同意。
- 商家注销后 30 天内删除其个人信息（法律要求保留的交易记录除外）。

## 4. 验收标准
- [ ] 对登录、注册、下单、发送验证码接口进行压测，超过阈值返回 429。
- [ ] 商品描述中插入 `<script>`、`<img onerror>`、`javascript:` 链接，均不执行。
- [ ] 商家 A 使用商家 B 的商品 ID、订单号调用接口，返回 404（不泄露资源是否存在）。
- [ ] 数据库中查不到明文私钥、明文卡密、明文令牌。
- [ ] 上传改了扩展名的可执行文件（如 `virus.exe` 改为 `virus.jpg`）被拒绝。
- [ ] 审计日志完整记录退款、导出卡密等操作。
- [ ] 安全响应头通过 securityheaders.com 评级 A。
